# نبرد قلعه‌ها برای Blazor Server و .NET 9

این بسته شامل فایل‌های واقعی Razor و C#، موتور بازی در JavaScript و یک میزبان نمونهٔ قابل‌اجراست. برای استفاده، نیازی به React، Node.js، Tailwind یا کتابخانهٔ NuGet شخص ثالث ندارید.

## کدام فایل‌ها را به پروژهٔ خودم اضافه کنم؟

فقط این دو مورد را از بسته به پروژهٔ اصلی خود کپی کنید:

- کل پوشهٔ `بازیها/قلعه/`، در کنار پوشه‌های منچ، ماری و کوییز شما.
- فایل `wwwroot/قلعه/castle.js`، داخل وب‌روت مشترک همان پروژه.

فایل‌های `Host/`، `Program.cs` و `CastleGame.Blazor.csproj` میزبان نمونه هستند. آن‌ها را روی فایل‌های پروژهٔ اصلی خود جایگزین نکنید.

ساختار فایل‌های بازی:

```text
بازیها/قلعه/
  _Imports.razor
  CastleModels.cs
  CastleGameService.cs
  CastleLevelsData.cs
  CastleGamePage.razor
  CastleGamePage.razor.cs
  CastleGamePage.razor.css
  CastleHud.razor
  CastleSettingsModal.razor
  CastleLevels.razor
  CastleHelp.razor
wwwroot/قلعه/
  castle.js
```

فضای نام همهٔ فایل‌های بازی `CastleGameFeature` است و از نام پروژهٔ شما مستقل است. لازم نیست آن را به نام پروژهٔ خود تغییر دهید. `_Imports.razor` را نیز حتماً کپی کنید؛ فضای نام و usingهای Razor را تنظیم می‌کند.

## معرفی سرویس

در `Program.cs` پروژهٔ خود، قبل از `builder.Build()` اضافه کنید:

```csharp
builder.Services.AddScoped<CastleGameFeature.CastleGameService>();
```

این سرویس نباید Singleton باشد؛ تنظیمات هر کاربر به circuit خودش تعلق دارد.

### خطای No registered service برای GameService

اگر خطای زیر را می‌بینید، فایل‌های بازی کپی شده‌اند اما سرویس در میزبان اصلی ثبت نشده است:

```text
Cannot provide a value for property 'GameService' ...
There is no registered service of type 'CastleGameFeature.CastleGameService'.
```

در `Program.cs` همان پروژه‌ای که اجرا می‌کنید (مثلاً `itWeb/Program.cs`)، این خط را درست قبل از ساخت برنامه قرار دهید:

```csharp
builder.Services.AddScoped<CastleGameFeature.CastleGameService>();

var app = builder.Build();
```

خط موجود `var app = builder.Build();` را تکرار نکنید؛ فقط ثبت سرویس را بالای آن اضافه کنید. ثبت در Program نمونهٔ داخل ZIP، سرویس را برای پروژهٔ اصلی شما ثبت نمی‌کند.

برنامه را کاملاً Stop کنید، سپس Rebuild و دوباره اجرا کنید. برای این تغییر به Hot Reload اکتفا نکنید، چون ثبت سرویس هنگام شروع برنامه انجام می‌شود. نیازی به تغییر `MainLayout.razor`، حذف `@inject` یا ساخت سرویس با `new` نیست.

## فعال‌بودن Blazor Server در .NET 9

در Blazor Web App با Interactive Server، تنظیمات زیر باید از قبل وجود داشته باشد. اگر وجود دارد آن را دوباره اضافه نکنید:

```csharp
builder.Services.AddRazorComponents().AddInteractiveServerComponents();

// بعد از builder.Build()
app.UseStaticFiles();
app.UseAntiforgery();
app.MapRazorComponents<App>().AddInteractiveServerRenderMode();
```

نام و فضای نام `App` در این مثال باید همان App پروژهٔ خودتان باشد؛ از Program نمونه برای جایگزین‌کردن کل Program پروژهٔ خود استفاده نکنید. `MapStaticAssets()` نیز در پروژه‌های .NET 9 می‌تواند مسئول سرو فایل‌های استاتیک باشد.

صفحهٔ بازی خودش `InteractiveServerRenderMode(prerender: false)` دارد. اگر پروژهٔ شما نسخهٔ قدیمی‌تر Blazor Server است که به .NET 9 ارتقا یافته و هنوز `_Host.cshtml`، `AddServerSideBlazor` و `MapBlazorHub` دارد، تنظیمات میزبان فعلی خود را حفظ کنید و تنها خط `@rendermode` را از `CastleGamePage.razor` بردارید؛ در آن میزبان همهٔ کامپوننت‌ها از قبل سروری هستند.

## اسکریپت و CSS

مسیر فیزیکی فایل `wwwroot/قلعه/castle.js` است. مسیر آن در مرورگر `قلعه/castle.js` است؛ در URL نباید `wwwroot` یا بک‌اسلش ویندوز نوشته شود.

هیچ تگ `<script src="قلعه/castle.js">` به App یا Host اضافه نکنید. این فایل یک ES module است و خود صفحه آن را در `OnAfterRenderAsync` از مسیر پایهٔ برنامه import می‌کند. این کار با مسیرهای زیرشاخه‌ای برنامه نیز سازگار است.

فایل `CastleGamePage.razor.css` به‌صورت CSS isolation ساخته می‌شود. پروژهٔ شما باید فایل CSS خودکار خودش، مانند `YourProject.styles.css`، را در App یا Host لود کند. این فایل در قالب‌های استاندارد Blazor وجود دارد. استایل بازی به Bootstrap و Tailwind وابسته نیست و روی بازی‌های دیگر اعمال نمی‌شود.

## آدرس بازی

پس از Build و اجرای پروژه، این آدرس را باز کنید:

```text
/games/castle
```

برای نمونه، اگر برنامه روی پورت 5099 اجرا شده باشد:

```text
http://localhost:5099/games/castle
```

فایل `.razor` یا `.csproj` را با دابل‌کلیک در مرورگر باز نکنید. Blazor Server نیاز به اجرای برنامهٔ ASP.NET Core دارد.

## اجرای نمونهٔ مستقل

برای تست بدون دست‌زدن به پروژهٔ اصلی:

1. .NET 9 SDK را روی سیستم داشته باشید.
2. فایل ZIP را استخراج کنید.
3. ترمینال را در پوشهٔ دارای `CastleGame.Blazor.csproj` باز کنید.
4. دستور زیر را اجرا کنید.

```bash
dotnet run --project CastleGame.Blazor.csproj --urls http://localhost:5099
```

سپس `http://localhost:5099/games/castle` را در مرورگر باز کنید. در Visual Studio نیز می‌توانید فایل csproj را باز کرده و پروژه را اجرا کنید. اگر .NET 9 روی سیستم نصب نیست، ابتدا SDK آن را نصب کنید.

## امکانات موجود

- ۳۰ مرحلهٔ کمپین و هوش مصنوعی کامل، جاده‌ها و مسیریابی، سه نوع قلعه (عادی، سریع و سنگین) و یک نوع برج دفاعی.
- همان رندر Canvas و جلوه‌های بازی وب، نه دایره‌های نمونه و توابع خالی.
- نمای ۲٫۵بعدی کم‌پلیگون با جزیره‌های صخره‌ای، دیواره‌های سایه‌دار، پل‌های سنگی، قلعه‌های چندوجهی، درخت و حرکت آب؛ تمام تصویرها با Canvas ساخته می‌شوند و فایل تصویری یا کتابخانهٔ سه‌بعدی خارجی لازم نیست.
- انتخاب با نگه‌داشتن کلیک چپ و عبور از روی قلعه‌های خودی، بدون محدودهٔ مستطیلی.
- انتقال به هم‌رنگ فقط با دوبار کلیک؛ رها کردن روی خودی یا یک کلیک نیرو نمی‌فرستد.
- درصد اعزام ۲۵، ۵۰، ۷۵ و ۱۰۰ درصد، افزایش خودکار ظرفیت، توقف، ادامه، تلاش دوباره و بازشدن مرحلهٔ بعد.
- سقف نهایی تولید قابل‌تنظیم (عدد دلخواه بین ۱ تا ۱۰۰۰ و گزینه‌های آماده) برای تمام قلعه‌های خودی و دشمن؛ قلعه‌ها با پُر ماندن ۵ ثانیه‌ای، خودکار ۱۰ واحد ظرفیت می‌گیرند.
- قلعه‌های خنثی خاکستری با نرخ معمول نوع ساختمان نیرو تولید می‌کنند، فقط تا سقف مستقل ۱۰ نفر. نیروی اولیهٔ قلعه‌های خنثی نیز حداکثر ۱۰ است و پس از تصرف، سقف تنظیم‌شدهٔ دو تیم جایگزین می‌شود.
- حذف هر ثانیهٔ بازی یک سرباز مازاد تا رسیدن به سقف. سرعت بازی روی زمان شبیه‌سازی اثر دارد و توقف، کسر و تولید را متوقف می‌کند.
- انتخاب نبرد در مسیر یا فقط در قلعه؛ شلیک برج یک قابلیت دفاعی مستقل است.
- سازندهٔ نقشهٔ تصادفی برای ۲ تا ۴ بازیکن: شمار قلعه‌های عادی، سریع و سنگین و تعداد برج‌ها را تنظیم کنید؛ هر بازیکن یک قلعهٔ شروع می‌گیرد و بقیه خنثی‌اند.
- ذخیرهٔ تنظیمات و پیشرفت در localStorage مرورگر، با رفتار امن وقتی ذخیره‌سازی مسدود باشد.
- میان‌برهای A، Space، Escape و اعداد 1 تا 4 وقتی Canvas فوکوس دارد؛ Shift برای افزودن به انتخاب.
- لغو RAF، رویدادها و observerها هنگام خروج از صفحه، و مدیریت JSDisconnectedException.

## معماری و محدودیت آفلاین

رابط کاربری و مدیریت قوانین/پیشرفت در Razor و C# است. موتور شبیه‌سازی، هوش مصنوعی، Canvas، صدا و رویدادهای ماوس در `castle.js` اجرا می‌شود. این بسته تبدیل صددرصد منطق بازی به C# نیست. این معماری برای جلوگیری از رفت‌وبرگشت شبکه در هر فریم در Blazor Server انتخاب شده است.

اطلاعات کوچک HUD حداکثر دو بار در ثانیه به سرور ارسال می‌شود؛ تنها یک درخواست هم‌زمان فعال است. امتیاز و بردِ اعلام‌شده از مرورگر برای بازی تک‌نفرهٔ محلی است و اعتبارسنجی امن برای مسابقات یا جایزهٔ واقعی به بک‌اند مستقل نیاز دارد.

هیچ فونت، CDN، تصویر یا API اینترنتی در بازی استفاده نمی‌شود. با اجرای سرور روی همان دستگاه یا شبکهٔ محلی، اینترنت عمومی لازم نیست؛ اما خود Blazor Server به اتصال فعال به سرور (SignalR) نیاز دارد و مانند HTML تک‌فایلی نمی‌توان آن را بدون سرور اجرا کرد. در قطع circuit، بازی خودکار متوقف می‌شود. مراحل و تنظیمات ذخیره می‌شوند؛ نبرد نیمه‌تمام پس از بارگذاری کامل صفحه از ابتدا شروع می‌شود.

## اگر چیزی نمایش داده نشد

1. `http://localhost:5099/قلعه/castle.js` باید کد JavaScript برگرداند، نه 404 یا HTML.
2. فایل `_Imports.razor` داخل پوشهٔ قلعه و ثبت Scoped سرویس را بررسی کنید.
3. مطمئن شوید صفحه Interactive Server است؛ Static SSR رویداد و JS interop تعاملی ندارد.
4. مطمئن شوید فایل `YourProject.styles.css` لود می‌شود.
5. اگر فایل castle.js را عوض کرده‌اید، مرورگر را با Ctrl+F5 تازه‌سازی کنید.

## تغییر موتور در آینده

### مرز برد برج و حرکت روی پل

در نسخهٔ فعلی، مرز برد برج بدون نیاز به انتخاب یا نگه‌داشتن نشانگر نمایش داده می‌شود. حلقهٔ رنگی متعلق به برج فعال و حلقهٔ خاکستری خط‌چین متعلق به برج خنثی است؛ برج خنثی همچنان شلیک نمی‌کند. شعاع نمایش با شعاع واقعی بررسی هدف در موتور یکسان است.

مسیر حرکت و پیش‌نمایش حمله اکنون از محور پل‌های واقعی استفاده می‌کند. مسیر فقط داخل محدودهٔ امن خشکی، قلعهٔ میانی را دور می‌زند و سپس دوباره به محور پل برمی‌گردد. جای پای سرباز و سایهٔ آن روی سطح زمین یا عرشه قرار دارد؛ ردیف‌های سرباز نیز در پیچ‌های تنگ به ستون باریک تبدیل می‌شوند. سرعت ۱٫۵ برابر سرباز سریع تغییر نکرده است.

برای اعمال این اصلاح در پروژهٔ موجود، `wwwroot/قلعه/castle.js` را از بستهٔ جدید جایگزین و صفحه را با Ctrl+F5 بارگذاری کنید. برای به‌روزشدن متن راهنما، فایل `بازیها/قلعه/CastleHelp.razor` نیز قابل جایگزینی است.

`wwwroot/قلعه/castle.js` فایل آمادهٔ اجرا و خوانا است؛ برای استفاده نیازی به کامپایل JavaScript ندارید. اطلاعات ۳۰ مرحله داخل همان فایل قرار دارد. کدهای C# و Razor معمولاً با Build استاندارد .NET ساخته می‌شوند.

### به‌روزرسانی نمای حجمی نقشه

موتور ترسیم جدید از هندسهٔ چندوجهی و سایه‌زنی روی Canvas استفاده می‌کند (۲٫۵بعدی، نه WebGL). شکل‌های بازی و جزیره‌ها طراحی مستقل دارند؛ هیچ تصویر، مدل یا فایل صوتی از بازی دیگری استفاده نشده است. پادگان باروی کنگره‌دار دارد، قلعهٔ سریع سقف بلوری و قلعهٔ سنگین گنبد زره‌دار دارد؛ برج دفاعی با بلور شناور مشخص می‌شود.

برای اعمال ظاهر جدید در پروژهٔ موجود، فایل `wwwroot/قلعه/castle.js` را جایگزین کنید. استایل `بازیها/قلعه/CastleGamePage.razor.css` نیز برای روشن‌ترشدن میدان نبرد به‌روزرسانی شده است. سپس Build و Ctrl+F5 انجام دهید. مختصات انتخاب، مسیرهای اعزام و قوانین نبرد تغییر نکرده‌اند؛ زوم و جابه‌جایی نقشه مثل قبل کار می‌کنند.

### نقشهٔ رندوم چندبازیکنه

از **تنظیمات → ساخت نقشهٔ رندوم** تعداد بازیکن‌ها (۲ تا ۴)، قلعهٔ عادی، سریع، سنگین و برج را تعیین کنید. گزینهٔ **نقشهٔ بزرگ با قابلیت زوم** فاصلهٔ قلعه‌ها را بیشتر و کنترل‌های زوم و جابه‌جایی نقشه را فعال می‌کند. نمونهٔ ۳ بازیکنهٔ ۳۰/۵/۲/۳، دقیقاً ۴۰ ساختمان دارد: سه قلعهٔ شروع از ترکیب قلعه‌ها به بازیکنان می‌رسد و ۳۷ ساختمان باقی‌مانده خنثی‌اند. نقشه پس از انتخاب، به شکل تصادفی و با قلعه‌های شروع دور از هم ساخته می‌شود؛ بازیکن‌های رقیب هوش مصنوعی مستقل دارند. برای هر بازیکن یک قلعهٔ شروع لازم است و مجموع ساختمان‌ها نباید از ۵۰ بیشتر شود.

تنظیمات آخرین نقشه در `localStorage` مرورگر حفظ می‌شود. پیروزی در نقشهٔ رندوم وارد پیشرفت لشکرکشی ۳۰مرحله‌ای نمی‌شود.

## صداهای طبیعی، زوم و قوانین راه‌ها

### صداهای طبیعی
- **پس‌زمینه:** باد ملایم و آواز پرنده‌های دور، ساخته‌شده با Web Audio (بدون فایل صوتی).
- **حرکت لشکر:** صدای قدم و خش‌خش زمین، فقط وقتی گروهی در راه است.
- **فتح قلعه:** آواز صعودی پرقدرت همراه با یک ضربهٔ کوبنده.

هر سه در تنظیمات قابل خاموش کردن هستند و صدای «بوق نبرد» جداگانه باقی مانده است.

### زوم
- **قرقرهٔ ماوس** روی نقشه زوم می‌کند و نقطهٔ زیر نشانگر سرِ جایش می‌ماند.
- دکمه‌های کوچک **+** و **−** کنار درصد زوم، و کلیک روی درصد برای بازگشت به نمای کامل.
- محدودهٔ زوم از ۱۰۰٪ تا ۳۰۰٪ است.

### قوانین راه‌ها (تنظیمات)
- **همهٔ قلعه‌ها به هم دسترسی داشته باشند:** هر جفت قلعه یک راه می‌سازد.
- **راه‌ها کاملاً رندوم:** راه‌ها با شانس یکسان انتخاب می‌شوند؛ هر قلعه دست‌کم یک راه نگه می‌دارد.
- **حداقل طول راه:** راهی که کوتاه‌تر از این مقدار (۰ تا ۴۰۰ پیکسل) باشد ساخته نمی‌شود، پس قلعه‌ها از هم دورتر می‌مانند.

این قوانین در نبرد جاری هم اعمال می‌شوند و نقشه دوباره ساخته می‌شود.

| قلعهٔ سنگین | سنگین | ۲ | ۲/۳ |

فقط یک نوع برج دفاعی وجود دارد و مثل قبل نیروی عادی تولید می‌کند و قابلیت دفاعی شلیک دارد؛ برج نوع چهارمی از سرباز ایجاد نمی‌کند. فاصلهٔ تولید اولیه: قلعهٔ عادی ۲ ثانیه، سریع و سنگین ۳ ثانیه، برج ۴ ثانیه.

نوع نیرو در قلعهٔ هم‌تیمی و پس از تصرف حفظ می‌شود. سرباز سریع با انتقال به قلعهٔ عادی کند نمی‌شود و سرباز عادی با انتقال به قلعهٔ سنگین قدرت اضافه نمی‌گیرد. قلعهٔ مختلط هنگام اعزام گروه‌های جدا می‌فرستد تا هر نوع با سرعت صحیح خودش حرکت کند. تلفات و آسیب جزئی ذخیره می‌شوند و با انتقال یا اعزام دوباره از بین نمی‌روند.

قدرت دوبرابر در حمله، دفاع قلعه و نبرد در مسیر اعمال می‌شود. نمایش تعداد سربازان و توان رزمی از هم جداست؛ مثلاً ۵۰ سرباز سنگینِ سالم، ۵۰ نفر هستند ولی ۱۰۰ واحد توان دارند. سقف تنظیمات همچنان تعداد افراد را محدود می‌کند، نه توان رزمی.

برای این به‌روزرسانی، `castle.js` و فایل‌های `CastleModels.cs`، `CastleHud.razor` و `CastleHelp.razor` را از بسته جایگزین کنید، پروژه را Build و مرورگر را با Ctrl+F5 بارگذاری کنید. ثبت سرویس و مسیر اسکریپت تغییر نکرده است.

### سقف نهایی و ظرفیت خودکار قلعه‌ها

سقف انتخابی تنظیمات برای هر دو تیم، سقف نهایی است. قلعه‌های تیمی از ظرفیت ۲۰ شروع می‌کنند و پس از ۵ ثانیه پُر ماندن ظرفیت، هر بار ۱۰ واحد ظرفیت می‌گیرند تا به سقف نهایی برسند. این روند خودکار است و دکمهٔ ارتقای دستی وجود ندارد.

اگر نسخهٔ قبلی را نصب کرده‌اید، `wwwroot/قلعه/castle.js` و فایل‌های `CastleHud.razor`، `CastleModels.cs`، `CastleSettingsModal.razor` و `CastleHelp.razor` را از بستهٔ جدید جایگزین کنید و پروژه را دوباره Build کنید. ثبت سرویس و مسیر فایل تغییر نکرده است.

نیروهای ورودی حاصل از انتقال یا تصرف می‌توانند موقتاً تعداد را بالاتر از سقف ببرند. این نیروها یک‌باره حذف نمی‌شوند؛ مطابق قانون سرریز، هر ثانیه یک نفر کم می‌شود تا دوباره به سقف برسد. این قانون برای هر دو تیم یکسان است.

### ساخت نقشهٔ رندوم

در **تنظیمات → ساخت نقشهٔ رندوم** تعداد بازیکنان را ۲ تا ۴ و شمار قلعه‌های عادی، سریع، سنگین و برج‌ها را مشخص کنید. مجموع ساختمان‌ها حداکثر ۵۰ است و باید حداقل به تعداد بازیکنان قلعه وجود داشته باشد تا هر بازیکن یک پایگاه شروع بگیرد. نمونه: ۳ بازیکن، ۳۰ قلعهٔ عادی، ۵ سریع، ۲ سنگین و ۳ برج، در مجموع ۴۰ ساختمان.

جایگاه‌ها تصادفی و از راه‌های متصل ساخته می‌شوند؛ قلعه‌های شروع بازیکنان دور از هم قرار می‌گیرند و بازیکن‌های دوم تا چهارم هوش مصنوعی مستقل دارند. قلعه‌های اضافه و برج‌ها خنثی‌اند. نقشهٔ ساخته‌شده از همان قواعد راه، انتقال، نبرد، سقف نیرو و برنده استفاده می‌کند؛ ابزار ویرایش دستی نقشه در این نسخه وجود ندارد.

### خروجی و ورودی مشترک تنظیمات

از بخش **تنظیمات → خروجی و ورودی تنظیمات** می‌توانید همهٔ تنظیمات فعلی (بلندی هر ۱۵ صدا، قدرت و سرعت سربازها، قوانین نبرد و راه‌ها، جلوه‌های نمایش و تنظیمات نقشهٔ رندوم) را با قالب استاندارد JSON (`battle-time-settings.json`) کپی یا دانلود کنید و در هر یک از نسخه‌های **وب، فایل آفلاین و Blazor Server** مستقیماً وارد نمایید. هنگام وارد کردن تنظیمات، پیشرفت مراحل بازشدهٔ بازیکن حفظ می‌شود.
